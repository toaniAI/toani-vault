### 组件说明

#### 1. 客户端层
- **Web 控制台**: React 前端，提供图形化管理界面
- **TypeScript SDK**: HTTP + WebSocket 客户端，支持浏览器和 Node.js
- **Rust SDK**: 原生客户端，提供类型安全的 API 访问
- **MCP Server**: Model Context Protocol 适配器，AI Agent 集成接口

#### 2. API Gateway 层
- **认证中间件**: PASETO Token 验证和 Scope 检查
- **路由分发**: 请求路由到对应的业务服务
- **审计日志**: 记录所有请求的审计信息
- **请求限流**: 防止滥用和 DDoS 攻击

#### 3. 业务服务层
- **凭证服务**: 凭证 CRUD、加密/解密、元数据管理
- **Token 服务**: Token 生成、验证、撤销、刷新
- **审计服务**: 审计日志记录、查询、报告
- **租户服务**: 租户管理、配额控制
- **Sandbox 服务**: TEE Sandbox 会话管理、浏览器自动化
- **认证服务**: 用户认证、权限管理

#### 4. TEE 层（Intel SGX Enclave）
- **Enclave 管理**: Enclave 生命周期、初始化、关闭
- **密钥管理**: 四层密钥派生、缓存、清理
- **远程认证**: SGX DCAP Quote 生成和验证
- **Sandbox 执行**: 安全的浏览器自动化沙箱

#### 5. 数据持久层
- **PostgreSQL**: 主数据库，存储凭证元数据、用户、租户等
- **Redis**: 缓存层，缓存热点数据、会话状态
- **HashiCorp Vault**: 敏感密钥存储（可选）
- **日志存储**: 审计日志、操作日志持久化

### 数据流

#### 凭证创建流程
```
客户端 → API Gateway → 认证 → 凭证服务 → TEE 加密 → PostgreSQL
                          ↓
                      审计服务 → 日志存储
```

#### 凭证解密流程
```
客户端 → API Gateway → 认证 → Scope 检查 → 凭证服务
                                              ↓
                                        TEE 解密
                                              ↓
                                        返回明文
                                              ↓
                                          审计记录
```

#### Sandbox 会话流程
```
客户端 → 创建会话 → Pool 分配沙箱 → Nsjail 启动 Chromium
                                    ↓
                              WebSocket 连接
                                    ↓
                              执行浏览器操作
                                    ↓
                              AI 审核 → 安全导出
```

## 安全架构设计

### TEE 安全执行环境

#### Enclave 边界保护
- **硬件隔离**: Intel SGX 提供 CPU 级别的内存加密和隔离
- **攻击面最小化**: 敏感操作限制在 Enclave 内部
- **内存加密**: Enclave 内存使用硬件加密，防止物理攻击
- **完整性保护**: Enclave 代码和数据经过测量和验证

#### Enclave 生命周期管理
```rust
pub enum EnclaveState {
    Uninitialized,   // 未初始化
    Initializing,    // 正在初始化
    Running,         // 已运行
    ShuttingDown,    // 正在关闭
    Shutdown,        // 已关闭
    Error,           // 错误状态
}
```

### 密钥层次架构

```
L0: Hardware Root Key (SGX Sealing Key)
  │ HKDF-Extract
  ▼
L1: Enclave Master Key (Enclave 内派生)
  │ HKDF-Expand(tenant_id + user_id)
  ▼
L2: User Vault Key (每用户独立，缓存 5 分钟)
  │ HKDF-Expand(credential_id + purpose)
  ▼
L3: Credential Encryption Key (每条凭证独立)
  │ AES-256-GCM
  ▼
Encrypted Credential
```

#### 密钥特性

| 层级 | 名称 | 生命周期 | 缓存 | 用途 |
|------|------|----------|------|------|
| L0 | Hardware Root Key | Enclave 生命周期 | 否 | 根密钥，派生 L1 |
| L1 | Enclave Master Key | Enclave 生命周期 | 是 | 派生 L2 用户密钥 |
| L2 | User Vault Key | 5 分钟 TTL | 是 | 派生 L3 凭证密钥 |
| L3 | Credential Key | 单次使用 | 否 | 加密凭证数据 |

### 远程认证系统

#### SGX DCAP 认证流程
```
┌─────────────────────────────────────────────────────────────┐
│              SGX DCAP 远程认证流程                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Verifier (挑战者)              Prover (Enclave)            │
│        │                              │                     │
│        │ 1. 生成随机挑战               │                     │
│        │ ─────────────────────────────>│                     │
│        │                              │                     │
│        │                              │ 2. 生成 Quote        │
│        │                              │    REPORT_DATA =    │
│        │                              │    hash(challenge + │
│        │                              │    identity)        │
│        │                              │                     │
│        │ 3. 返回 Quote                 │                     │
│        │ <─────────────────────────────│                     │
│        │                              │                     │
│        │ 4. 验证 Quote                 │                     │
│        │    - 验证 ECDSA 签名          │                     │
│        │    - 验证 MRENCLAVE           │                     │
│        │    - 验证挑战绑定             │                     │
│        │                              │                     │
│        │ 5. 建立安全通道               │                     │
│        │ ─────────────────────────────>│                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 认证安全特性
- **防重放攻击**: 每次挑战随机生成，仅使用一次
- **身份绑定**: Quote 中的 REPORT_DATA 绑定挑战和 Enclave 身份
- **新鲜性保证**: 挑战严格时间限制（默认 5 分钟）
- **不可否认**: ECDSA P-256 签名提供强不可否认性
- **测量值白名单**: 只允许特定 Enclave 测量值通过认证

#### 沙箱安全特性

| 特性 | 实现 | 安全等级 |
|------|------|----------|
| **Namespace 隔离** | PID/Network/Mount/IPC/UTS 隔离 | 🔴 Critical |

| **cgroups 限制** | CPU/内存/进程/IO 资源限制 | 🟠 High |
| **凭证隔离** | 每会话独立的凭证命名空间 | 🔴 Critical |
| **AI 操作审核** | 每个操作经过 LLM 安全审核 | 🟠 High |
| **提示词安全** | 多层注入检测和隔离构建 | 🟠 High |
| **安全导出** | 截图/数据导出前 AI 审核 + 数字签名 | 🟠 High |
| **无根运行** | 沙箱内以非特权用户运行 | 🟡 Medium |

### 密码学安全体系

#### 加密算法
- **对称加密**: AES-256-GCM（认证加密）
- **密钥派生**: HKDF-SHA-256
- **非对称加密**: ECDSA P-256（远程认证）
- **哈希**: SHA-256

#### 安全内存管理
- **ZeroizeOnDrop**: 密钥结构体实现自动清零
- **TTL 缓存**: 用户密钥缓存 5 分钟过期自动清理
- **后台调度器**: 定期清理过期密钥
- **受保护内存**: 敏感数据存储在受保护内存区域

#### 密钥清理策略
```rust
// 自动清理（作用域结束时）
{
    let key = CredentialKey::new(...);
    // 使用密钥...
} // key 自动 zeroize

// 手动清理
KeyCleaner::clear_bytes(&mut sensitive_data);
KeyCleaner::deep_clear(&mut key_material);
```

## 数据架构设计

### 数据库设计

#### 核心表结构

**凭证表 (credentials)**
```sql
CREATE TABLE credentials (
    credential_id UUID PRIMARY KEY,      -- UUID v7 时间排序
    tenant_id UUID NOT NULL,              -- 租户 ID
    user_id_hash VARCHAR(64) NOT NULL,    -- 用户 ID 哈希
    service_id VARCHAR(255) NOT NULL,     -- 服务标识
    credential_type VARCHAR(50) NOT NULL, -- 凭证类型
    encrypted_payload JSONB NOT NULL,     -- 加密载荷
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL,
    expires_at TIMESTAMP,
    is_deleted BOOLEAN DEFAULT FALSE,
    deleted_at TIMESTAMP,
    
    -- 索引
    INDEX idx_tenant_user (tenant_id, user_id_hash),
    INDEX idx_service (tenant_id, service_id),
    INDEX idx_created (created_at DESC)
);
```

**用户表 (users)**
```sql
CREATE TABLE users (
    user_id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL,
    username VARCHAR(255) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    email VARCHAR(255),
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL,
    
    INDEX idx_tenant (tenant_id),
    INDEX idx_username (tenant_id, username) UNIQUE
);
```

**Token 表 (tokens)**
```sql
CREATE TABLE tokens (
    jti UUID PRIMARY KEY,                 -- Token 唯一标识
    user_id UUID NOT NULL,
    tenant_id UUID NOT NULL,
    scopes TEXT[] NOT NULL,               -- Scope 列表
    credential_ids UUID[],                -- 受限凭证白名单
    issued_at TIMESTAMP NOT NULL,
    expires_at TIMESTAMP NOT NULL,
    revoked_at TIMESTAMP,
    used_at TIMESTAMP,                    -- 单次使用检测
    
    INDEX idx_user (user_id),
    INDEX idx_expires (expires_at),
    INDEX idx_jti_used (jti, used_at)
);
```

**审计日志表 (audit_logs)**
```sql
CREATE TABLE audit_logs (
    audit_id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL,
    user_id UUID,
    operation VARCHAR(100) NOT NULL,
    resource_type VARCHAR(50),
    resource_id UUID,
    result VARCHAR(20) NOT NULL,
    ip_address INET,
    user_agent TEXT,
    metadata JSONB,
    created_at TIMESTAMP NOT NULL,
    
    INDEX idx_tenant_time (tenant_id, created_at DESC),
    INDEX idx_user (user_id, created_at DESC),
    INDEX idx_operation (operation)
);
```

### 多租户隔离

#### Schema-per-Tenant 架构
- 每个租户拥有独立的数据库 Schema
- Schema 名称：`tenant_{tenant_id}`
- 租户间数据物理隔离

#### 行级安全（RLS）
```sql
-- 启用 RLS
ALTER TABLE credentials ENABLE ROW LEVEL SECURITY;

-- 创建策略
CREATE POLICY tenant_isolation ON credentials
    USING (tenant_id = current_setting('app.current_tenant')::uuid);
```

#### 租户验证
- 所有查询自动附加租户过滤条件
- 应用层验证租户权限
- 数据库层 RLS 双重保护

### 数据加密

#### 加密载荷格式
```json
{
  "version": 2,
  "algorithm": "AES-256-GCM",
  "kdf": "HKDF-SHA-256",
  "nonce": "base64_encoded_12_bytes",
  "auth_tag": "base64_encoded_16_bytes",
  "ciphertext": "base64_encoded_encrypted_data"
}
```

#### 加密流程
1. 从 L2 User Key 派生 L3 Credential Key
2. 生成随机 Nonce（12 bytes）
3. 使用 AES-256-GCM 加密明文数据
4. 组合 Nonce + Ciphertext + Auth Tag
5. 存储加密载荷到数据库

### Intel SGX 部署要求

#### 硬件要求
- **CPU**: Intel Core 6 代 + 或 Xeon E3/E-系列
- **BIOS**: 启用 Intel SGX 支持
- **内存**: 足够的 EPC（Enclave Page Cache）内存

#### 软件要求
- **操作系统**: Linux（Ubuntu 20.04+、CentOS 8+）
- **SGX 驱动**: Intel SGX DCAP 驱动
- **SGX SDK**: Intel SGX SDK

#### 检测 SGX 支持
```bash
# 检查 CPU 支持
cat /proc/cpuinfo | grep sgx

# 检查设备节点
ls -la /dev/sgx*

# 检查 EPC 内存
cat /sys/kernel/debug/sgx/epc_size
```

#### 构建 SGX 版本
```bash
# 启用 SGX 特性构建
cargo build --features sgx

# 运行测试
cargo test --features sgx
```
